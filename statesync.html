Celestia State Sync

Fast node synchronization via state sync protocol. No need to sync from genesis.

Snapshots State Sync Peers
State Sync allows your node to sync by downloading a recent state snapshot from peers, without replaying all historical blocks. This is typically faster than block-by-block sync. Our node publishes CometBFT state-sync snapshots every 1500 blocks (keeps last 2).

State Sync

WARNING: This will reset your node data. If you are running a validator, back up data/priv_validator_state.json FIRST to avoid double-signing after restore.
1Stop the node
sudo systemctl stop celestia-appd
2Back up validator state (validators only)
cp ~/.celestia-app/data/priv_validator_state.json ~/.celestia-app/priv_validator_state.json.bak
3Run state sync
SNAP_RPC=https://rpc.apollo-validator.eu/celestia/
LATEST_HEIGHT=$(curl -s $SNAP_RPC/block | jq -r .result.block.header.height); \
BLOCK_HEIGHT=$((LATEST_HEIGHT - 1000)); \
TRUST_HASH=$(curl -s "$SNAP_RPC/block?height=$BLOCK_HEIGHT" | jq -r .result.block_id.hash)

echo $LATEST_HEIGHT $BLOCK_HEIGHT $TRUST_HASH

sed -i.bak -E "s|^(enable[[:space:]]+=[[:space:]]+).*$|\1true| ; \
s|^(rpc_servers[[:space:]]+=[[:space:]]+).*$|\1\"$SNAP_RPC,https://celestia-mainnet-rpc.itrocket.net\"| ; \
s|^(trust_height[[:space:]]+=[[:space:]]+).*$|\1$BLOCK_HEIGHT| ; \
s|^(trust_hash[[:space:]]+=[[:space:]]+).*$|\1\"$TRUST_HASH\"|" ~/.celestia-app/config/config.toml
4Reset node data
celestia-appd tendermint unsafe-reset-all --home ~/.celestia-app --keep-addr-book
5Restore validator state (validators only)
cp ~/.celestia-app/priv_validator_state.json.bak ~/.celestia-app/data/priv_validator_state.json
6Start node
sudo systemctl restart celestia-appd && journalctl -fu celestia-appd -n1000 -o cat
7Verify sync
curl -s http://127.0.0.1:36657/status | jq -r .result.sync_info.catching_up
# expect: false once synced (can take a few minutes after state sync)
